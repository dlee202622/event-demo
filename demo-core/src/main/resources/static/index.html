DDD Event-Driven Demo - RabbitMQ 集成测试
测试说明：本页面测试 demo-core 模块的 RabbitMQ 集成。创建订单后，事件会通过以下流程处理：
订单服务 → Spring Event → OutboxHandler → OutboxRelay → RabbitMQ → OrderEventConsumer → Spring Event → Inventory/Loyalty Listeners
1. 创建订单（触发事件流）
2. 事件处理流程
步骤 1：订单服务创建订单，发布 OrderCreatedEvent（Spring 进程内事件）
步骤 2：DomainEventOutboxHandler 监听事件，写入 OutboxStore（内存版发件箱）
步骤 3：InventoryEventListener、OrderNotificationHandler 等进程内订阅者立即处理事件
步骤 4：OutboxRelay 定时任务（每 3 秒）将 PENDING 事件发送到 RabbitMQ
步骤 5：OrderEventConsumer 从 RabbitMQ 队列接收消息
步骤 6：消费者反序列化 JSON，重新发布为 Spring ApplicationEvent
步骤 7：事件订阅者再次处理（演示分布式场景下的跨服务消费）
3. 查看日志
提示：请在终端查看应用日志，搜索以下关键字观察事件流转：
tail -f /tmp/demo-core.log | grep -E "事件发布|Outbox→RabbitMQ|RabbitMQ→Spring|库存上下文"
[事件发布] - Spring 进程内事件发布
[库存上下文] 收到 OrderCreatedEvent - 进程内订阅者处理
[Outbox→RabbitMQ] 发送成功 - OutboxRelay 发送到 RabbitMQ
[RabbitMQ→Spring] 收到消息 - 消费者从 RabbitMQ 接收
[RabbitMQ→Spring] 事件已发布 - 消费者重新发布为 Spring 事件
