# 教学代码注释规范

## 目标

读者打开一个类，不查外部资料也能回答：

1. 这个类解决什么问题，什么时候该用？
2. 这个方法的参数单位是什么，返回什么，失败会怎样？
3. 这一行为什么这样写？换一种写法会出什么问题？

注释写“为什么”和“坑”，不写代码已经说清楚的“是什么”。

## 密度要求

| 文件类型 | 注释行 / 总行数 | 说明 |
|----------|----------------|------|
| 核心算法 / 并发 / 缓存类 | ≥ 25% | 每个分支、每个时间计算都要有解释 |
| 控制器 | ≥ 12% | 每个端点写用途、参数、预期输出 |
| 配置 / 仓储 | ≥ 10% | 解释非默认配置和 SQL 意图 |
| record / DTO / 常量 | 不强制 | 不写“这是一个 DTO”这种废话 |

密度只是下限。一个 40 行的类写 10 行有效注释，比 200 行类写 50 行套话更有价值。

## 六层注释

### 1. 类级 Javadoc

必须包含：定位、适用场景、关键实现、坑/限制、替代方案。

```java
/**
 * 手写分布式锁：SET NX PX 原子抢占 + Lua 校验持有者后释放/续期。
 *
 * <p>刻意不自动续期，用来观察业务执行超过 TTL 后临界区重叠。
 * 生产环境要么自己起看门狗，要么直接用 Redisson。</p>
 *
 * <p>限制：主从切换可能丢锁；释放与续期只能保证“不误删别人的锁”，
 * 不能替代 fencing token 对下游写入的保护。</p>
 */
```

### 2. 公共方法

写参数单位、返回值含义、边界行为。

```java
/**
 * @param ttlMillis 锁的存活时间，单位毫秒；必须大于一次业务执行时间
 * @return true 表示抢到锁；false 表示已被其他持有者占用
 */
public boolean tryLock(String key, String holder, long ttlMillis) {
```

### 3. 分支与循环

解释“为什么走这条分支”，而不是复述条件。

```java
// 锁已过期：说明业务执行时间超过了 TTL，此时 B 拿到锁会造成临界区重叠
if (aHolding.get()) {
    overlap.set(true);
}
```

### 4. Magic number

每个非显然的数字都要交代来源或约束。

```java
// 采样间隔 200ms：小于最短 TTL(500ms)，能观察到 TTL 递减和续期跳变
scheduler.scheduleAtFixedRate(sampler, 100, 200, TimeUnit.MILLISECONDS);
```

### 5. 并发与顺序不变量

明确“谁先谁后”“哪个原子操作保证了什么”。

```java
// 先更新 DB 再删缓存：若先删缓存，写库完成前的读请求会把旧值重新回填
repository.update(id, name, price);
redis.delete(cacheKey);
```

### 6. Lua / SQL / 脚本

Lua 的每个分支、返回值格式、key/arg 约定都要写。

```lua
-- 返回 '允许|剩余|重试毫秒'：单字符串避免客户端对数组类型的映射差异
-- ARGV[1]=now(ms) ARGV[2]=windowMs ARGV[3]=limit
local windowIndex = math.floor(now / windowMs)
```

## 正反例

| 反例 | 正例 |
|------|------|
| `// 删除缓存` | `// 删除而不是更新缓存：并发写时更新可能被旧值覆盖，删除让下次读回源` |
| `// 设置 TTL` | `// TTL 取 2 个窗口：保证上一窗口计数在边界后仍可被加权读取` |
| `// 睡 100ms` | `// 等读线程拿到旧快照后再写库，制造“删除后回填旧值”的确定性时序` |
| `// 加锁` | `// 锁粒度为单次自增：锁住整个循环会让并发退化成串行，观察不到竞争` |
| `// 返回结果` | `// 剩余额度向下取整：估算值可能是小数，返回给调用方时不能出现 2.7 个名额` |

## Lua 注释约定

- 顶部写清 `KEYS` / `ARGV` 的含义和单位。
- 顶部写清返回值格式，例如 `允许(1/0)|剩余|重试毫秒`。
- 每个 `if` 分支写触发条件。
- 时间计算写清基准（客户端时间 vs Redis `TIME`）和时钟偏差风险。
- 清理旧数据的语句写清保留范围（例如“保留当前和上一窗口”）。

## 审计方法

```bash
node .qoder/skills/tech-demo-builder/scripts/comment-audit.mjs <src-dir>
```

脚本输出：

- 总体注释率
- 低于阈值的文件（按缺口排序）
- 公共方法前 3 行内没有注释的清单

`--strict` 模式下，60 行以上的文件低于阈值会返回非 0，适合提交前检查。
record/DTO 的“未注释公共方法”可以忽略，不要为了指标写废话。

## 复查清单

- [ ] 每个类都有“为什么存在 + 坑”
- [ ] 每个公共方法都有参数/返回/失败说明
- [ ] 每个非显然分支和数字都有解释
- [ ] 并发/时序代码标出不变量
- [ ] Lua 有 KEYS/ARGV/返回值/分支说明
- [ ] 没有“设置值”“返回结果”这类复述
- [ ] 注释与代码同步，没有过期描述
