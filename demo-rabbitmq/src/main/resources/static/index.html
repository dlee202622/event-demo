RabbitMQ (8081)
RocketMQ (8082)
可靠性场景
1. 简单队列
POST /api/rabbitmq/simple
最基本的点对点消息发送
2. 工作队列
POST /api/rabbitmq/work
多消费者竞争消费，展示负载均衡和手动 ACK
3. 发布/订阅 (Fanout)
POST /api/rabbitmq/fanout
消息广播到所有绑定队列（queue-a 和 queue-b 同时收到）
4. 路由模式 (Direct)
POST /api/rabbitmq/direct
按 routing key 精确路由：order.created → order 队列，order.paid → payment 队列
5. 主题模式 (Topic)
POST /api/rabbitmq/topic
通配符路由：* 匹配一个词，# 匹配零或多个词。order.* 匹配所有 order 事件
6. 消息确认 (Publisher Confirm)
POST /api/rabbitmq/confirm
开启 correlated 确认模式，生产者注册 ConfirmCallback 确认消息到达 Broker
7. 死信队列 (DLQ)
POST /api/rabbitmq/dlx
消息被拒绝后自动转入死信队列（TTL 3s + reject），由 DLQ 消费者处理
1. 基础收发
POST /api/rocketmq/simple
最基本的消息发送与消费
2. 顺序消息
POST /api/rocketmq/orderly
同一 orderKey 的消息发送到同一队列，保证 FIFO 消费顺序
3. 标签过滤
POST /api/rocketmq/tag
按 Tag 过滤消费：消费者只接收 TagA 消息，TagB 消息被过滤
4. 延迟消息
POST /api/rocketmq/delay
定时投递：delayLevel 1=1s, 2=5s, 3=10s, 4=30s, 5=1m ...
5. 事务消息
POST /api/rocketmq/transaction
半消息 + 本地事务 + 回查，实现分布式事务最终一致性
6. 广播消费
POST /api/rocketmq/broadcast
同一消费者组的所有实例都收到每条消息，适用于通知类场景
使用说明
先启动对应模块，再按「暂停 → 发送 → 查状态 → 恢复」操作。幂等去重表在进程内存里， 重启即清空；RocketMQ 新 Topic 首次发送后，消费端刷新路由最多需要约 30 秒； 持久化演示请用 docker compose restart 重启 Broker，不要用 down/up。
RabbitMQ · 幂等消费
POST /api/rabbitmq/idempotent
同一业务 ID 连发两条，消费端只处理一次，第二条打印 duplicate ignored
RabbitMQ · 顺序消费
POST /api/rabbitmq/ordered | /unordered
有序队列单消费者；无序队列 4 个并发消费者做反例，观察日志顺序差异
RabbitMQ · 消息积压
/api/rabbitmq/backlog/*
先暂停消费者，再批量发送并查状态，最后恢复消费
RabbitMQ · 消息持久化
/api/rabbitmq/persistence/*
暂停后发送 → docker compose restart rabbitmq → 查状态 → 恢复；persistent=false 可做对比
RocketMQ · 幂等消费
POST /api/rocketmq/idempotent
同一业务 ID 连发两条，消费端只处理一次
RocketMQ · 顺序消费
POST /api/rocketmq/ordered-batch | /unordered
同一 orderKey 顺序发送；无序 topic 用并发消费做反例
RocketMQ · 消息积压
/api/rocketmq/backlog/*
先暂停消费者，再批量发送；堆积量到 Dashboard 消费者页看 Diff
RocketMQ · 消息持久化
/api/rocketmq/persistence/*
暂停后发送 → docker compose restart rocketmq-broker → 恢复，验证消息重新投递
RabbitMQ · 消息优先级
/api/rabbitmq/priority/*
先暂停，再按 1 / 5 / 9 各发 5 条，恢复后日志顺序应为 9 → 5 → 1（仅队列中排队的消息生效）
RocketMQ · 优先级隔离
/api/rocketmq/priority/*
RocketMQ 无原生优先级，按 level 拆 Topic + 独立消费者。先暂停 low 发 40 条，再发 high，high 仍立即消费
