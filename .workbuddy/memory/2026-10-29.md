## MySQL 原理与数据结构图文教程（tech-demo-builder skill）

- 产出：`docs/mysql-guide.html`（单文件教程，1813 行，check-guide 校验通过）+ `docs/mysql-guide-labs/`（14 个可复现实验脚本）。
- 用户选择：不做代码模块，只要 HTML 教程；覆盖索引/B+ 树、事务 MVCC、Buffer Pool/日志、锁与死锁四条线；面向「用过 MySQL 但没深挖」的读者。
- 实测环境：仓库 docker-compose 的 mysql:8.4.13（root/123456），独立库 `demo_mysql_principle`，未动业务库。
- 关键实测数字（2026-10-29）：
  - 页分裂：30 万行插入 递增主键 6.25s vs UUID 主键 13.01s（2.1×），文件 60MB vs 72MB
  - 覆盖索引：逻辑读 回表 12,043 vs 覆盖 23~31（约 400×），用 FLUSH STATUS + Innodb_buffer_pool_read_requests 差值法
  - 最左前缀：key_len 4/8/12 递进；跳过最左列 type=ALL
  - 深分页：LIMIT 900000,10 = 1.81s/次，游标法 0.75ms（2400×），延迟关联仅快 34%（主键排序场景延迟关联不是银弹）
  - MVCC：RR 事务内快照读见旧值、FOR UPDATE 当前读见新值；RC 每次读重拍快照
  - 死锁：双会话互锁复现 ERROR 1213 (40001)，InnoDB 回滚代价小方
  - 间隙锁：范围 FOR UPDATE 冻结区间插入 2s
  - flush=1 vs 2：5000 次提交 10.74s vs 9.47s（本机 Docker fsync 便宜，差距仅 12%，教程里已注明不能当普适结论）
- 教程坑位记录：check-guide.mjs 只认「行首 --/#」注释，行尾注释不算数；FLUSH STATUS 在脚本里实际表现为会话累计计数，需取差值。
